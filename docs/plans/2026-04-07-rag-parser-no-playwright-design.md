# RAG Parser No-Playwright Design

**Date:** 2026-04-07

## Goal

Make the initial PubMed link collection step in `RAG_seminar.ipynb` work in Google Colab without depending on Playwright or Chromium system libraries.

## Root Cause

The failing step is the `parser.py` helper generated by the notebook. It uses `AsyncChromiumLoader`, which launches Playwright Chromium. In Colab this failed because the browser process could not start due to missing Linux shared libraries. The task itself is only extracting article links from the PubMed search result page, so the browser dependency is disproportionate to the actual need.

## Chosen Approach

Replace the browser-based parser with a simple HTTP parser built on `requests` and `BeautifulSoup`:
- fetch the PubMed search page with `requests`
- parse the HTML with `BeautifulSoup`
- extract article links from anchors with class `docsum-title`
- keep the same output files: `page.html` and `links.txt`

This preserves the seminar flow while removing the fragile runtime dependency.

## Alternatives Considered

### 1. Keep Playwright and add more Colab setup

Pros:
- Minimal code changes in parser logic

Cons:
- Still depends on Chromium runtime libraries
- Slower and more failure-prone in Colab
- Solves infrastructure, not the actual overkill

Rejected.

### 2. Switch parser step to `requests + BeautifulSoup`

Pros:
- No browser dependency
- Faster and simpler
- Better fit for Colab

Cons:
- Assumes the needed links are already present in server HTML

Chosen.

## Scope

### In scope
- Update the explanatory markdown in `RAG_seminar.ipynb`
- Replace `parser.py` cell contents with synchronous `requests + BeautifulSoup`
- Remove Playwright setup from the notebook and `requirements_rag.txt`
- Update docs/tests to reflect the new parser contract

### Out of scope
- Rewriting the broader RAG seminar
- Changing downstream retrieval or QA sections

## Testing Strategy

- Add notebook-structure tests asserting Playwright/`AsyncChromiumLoader` are removed from the parser flow
- Assert `requests.get(...)` and `BeautifulSoup` based parsing exist in the notebook
- Run the full local test suite and notebook syntax smoke
