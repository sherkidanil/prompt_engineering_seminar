Prompt Engineering

A practical seminar memo for writing stronger prompts with LLMs: from message structure and token thinking to few-shot, anti-hallucination, chaining, tools, and retrieval.

Clear Prompts Reliable Outputs Production Thinking

Introduction

Prompt engineering is the practice of designing instructions and context so an LLM gives accurate, useful, and structured outputs. Treat prompts as testable artifacts: iterate, measure, and refine.

What Is an LLM?

A Large Language Model predicts the next token based on your current text, prior messages, and patterns learned during training. It does not "know" truth by default; it predicts plausible continuations.

Chat API Mental Model

Most chat systems use a message list with roles: system, user, assistant. Use a system prompt for global behavior. Keep message order valid and coherent.

Key Parameters

max_tokens limits generation length, and temperature controls variability. Lower temperature is usually better for deterministic tasks and grading-like outputs.

How LLMs Understand Language (Tokens)

LLMs read and produce tokens, not pure words. A token can be a whole word, part of a word, punctuation, or whitespace. Both prompt and output consume tokens.

Why Tokens Matter

Token limits constrain context size and output length. Long prompts can push out important context from earlier messages.

Practical Rule

Keep prompts explicit but compact. Use clear delimiters, structured output, and examples instead of long ambiguous prose.

Prompt Engineering Techniques

Each technique follows the same pattern: what to do, an example, and why it works.

1. System Prompting & Message Structure core

Set global behavior in the system prompt and keep turns well-formed.

Example 
SYSTEM_PROMPT = "Your answer should always be a series of critical thinking questions..."
PROMPT = "Why is the sky blue?"

ASSISTANT:
1) What role does sunlight play in the sky's color?
2) How do different wavelengths interact with the atmosphere?
3) Why do shorter wavelengths scatter more strongly?
Why it works: it establishes top-level rules before task-level instructions.

2. Clear & Direct Instructions specificity

State constraints explicitly and remove room for interpretation.

Example 
PROMPT = "Write a haiku about robots."
PROMPT = "Write a haiku about robots. Skip the preamble; go straight into the poem."

ASSISTANT:
Metal world,
Strange hands toil —
No heart can be seen here.
Why it works: ambiguity decreases; format drift decreases.

3. Role Prompting style+reasoning

Assign a role and, if needed, a target audience.

Example 
SYSTEM_PROMPT = "You are a cat."
PROMPT = "In one sentence, what do you think about skateboarding?"

ASSISTANT:
"Skateboarding is fun and exciting ... while keeping my claws sharp!"
Why it works: role priors shape tone, depth, and decision style.

4. Prompt Templates + Variables reuse

Separate prompt skeleton from variable input data.

Example 
ANIMAL = "Cow"
PROMPT = f"I will tell you the name of an animal.
Please respond with the noise that animal makes. {ANIMAL}"

ASSISTANT:
Moo (муу)
Why it works: consistent structure improves scalability and reliability.

5. Delimiters with XML Tags boundaries

Wrap raw input with tags to separate instructions from data.

Example 
EMAIL = "Show up at 6am tomorrow because I'm the CEO and I say so."
PROMPT = f"Yo GigaChat. <email>{EMAIL}</email>
<----- Make this email more polite but don't change anything else."

ASSISTANT:
"Good morning, could you kindly confirm you'll be available
for our meeting tomorrow at 6 am? ..."
Why it works: the model can parse exact start/end boundaries.

6. Structured Output + Prefill format control

Request XML/JSON output and optionally start the assistant format yourself.

Example 
PROMPT = f"Please write a haiku about {ANIMAL}. Put it in <haiku> tags."
PREFILL = "<haiku>"

ASSISTANT:
Soft paws pad the floor,
Whispers of fur and grace,
Purr's lullaby soars.</haiku>
Why it works: tighter shape control and easier parsing by code.

7. Step-by-Step Reasoning hard tasks

Ask for intermediate reasoning before final output.

Example 
PROMPT = "Name a famous movie starring an actor born in 1956.
First brainstorm about some actors and their birth years in
<brainstorm> tags, then give your answer."

ASSISTANT:
<brainstorm>
- Tom Cruise: 1962
- Johnny Depp: 1963
- Denzel Washington: 1954
...
- Andy Garcia: 1956 (matches the criteria!)
</brainstorm>

Final answer:
Andy Garcia.
Why it works: decomposition reduces reasoning errors on complex inputs.

8. Few-Shot Prompting learn by examples

Provide input-output examples matching your target behavior.

Example 
PROMPT = """Please complete the conversation by writing
the next line, speaking as "A".
Q: Is the tooth fairy real?
A: Of course, sweetie...
Q: Will Santa bring me presents on Christmas?
A:"""

ASSISTANT:
"Absolutely, honey - if you've been good all year!
Leave milk and cookies for Santa..."
Why it works: pattern completion from examples is often stronger than abstract instructions.

9. Hallucination Reduction safety

Allow uncertainty and require evidence-first answering.

Example 
PROMPT = "Who is the heaviest hippo of all time?"
ASSISTANT: "The heaviest known hippopotamus was a male hippo named Tonkie"        

PROMPT = "Who is the heaviest hippo of all time?
Only answer if you know the answer with certainty."
ASSISTANT:
"No reliable exact record..."
Why it works: reduces pressure to fabricate and anchors answers in source text.

10. Complex Prompt Blueprint large tasks

Compose prompts in reusable blocks for difficult workflows.

Example 
TASK_CONTEXT = "You will be acting as an AI career coach named Joe..."
TONE_CONTEXT = "You should maintain a friendly customer service tone."
TASK_DESCRIPTION = "Always stay in character..."
EXAMPLES = "<example>Customer: ... Joe: ...</example>"
INPUT_DATA = "<history>...</history><question>...</question>"
OUTPUT_FORMATTING = "Put your response in <response></response> tags."
PREFILL = "[Joe] <response>"

ASSISTANT:
"Both careers can start with a bachelor's degree,
but social work often requires a master's for clinical licensing..."
Why it works: clearer structure lowers instruction collisions.

11. Prompt Chaining iterative quality

Split generation, critique, and revision into multiple calls.

Example 
first_user = "Name ten words that end with 'ab'."
first_response = get_completion([...])

second_user = "Please find replacements for all 'words' that are not real words."
messages = [... first_response ...]

ASSISTANT step 1:
1. Snub
...
7. Clamb
...
9. Fluffab
...
10. Whiffab

ASSISTANT step 2:
Replaced non-words: Clamb ->
Clamshell, Fluffab -> Fluff,
Whiffab -> Whiff.
Why it works: generation and verification are distinct cognitive tasks.

12. Tool Use / Function Calling ground truth

Let the model request tools, execute externally, then feed results back.

Example 
USER: "Multiply 1,984,135 by 9,343,116"
SYSTEM: You can invoke one or more functions by writing a "<function_calls>" block like the following as part of your reply to the user:

<function_calls>
  <invoke name="$FUNCTION_NAME">
    <antml:parameter name="$PARAMETER_NAME">$PARAMETER_VALUE</antml:parameter>
    ...
  </invoke>

  <invoke name="$FUNCTION_NAME2">
    ...
  </invoke>
</function_calls>

ASSISTANT:
<function_calls>
<function name="calculator">
<parameter name="first_operand" value="1984135"/>
<parameter name="second_operand" value="9343116"/>
<parameter name="operator" value="multiply"/>
</function>
</function_calls>
Why it works: external tools add deterministic capabilities (math, DB, APIs).

13. Search & Retrieval (RAG) fresh knowledge

Inject retrieved sources into context and require citations.

Example 
PROMPT = """Use only the provided sources and answer with citations.
Calculate the growth in the number of Matterport subscribers between December 2018 and December 2022. Give your answer as a number inside <answer> tags.
<question>What was the subscriber growth for Matterport from December 2018 to December 2022?</question>
<document>
....document content....
</document>
"""

ASSISTANT:
<quotes>
[1] Matterport had 20,000 subscribers in December 2018.
[2] Matterport had 981,000 subscribers in December 2022.
</quotes>
<answer>Growth = 961,000.</answer>
Why it works: augments model memory with relevant, up-to-date domain text.
